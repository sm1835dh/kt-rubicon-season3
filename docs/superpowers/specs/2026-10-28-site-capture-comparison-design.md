# 국가별 Samsung.com 화면 비교 캡쳐 도구 — 설계

- 작성일: 2026-10-28 (KST)
- 1차 대상: Galaxy Z Fold8 Ultra 구매 페이지 (UK / CA-EN / CA-FR / US)
- 관련 문서: `data/doc/rubicon_country_expansion_site_comparison.md` (정적 수집 기반 비교 보고서)

## 1. 의도

루비콘 프로젝트는 UK를 기준으로 CA, US 순서로 국가를 확산합니다. 기존 비교 보고서는 정적 HTML 기준이라 실제 화면에 무엇이 어떻게 보이는지는 확인하지 못했습니다.

이 도구는 같은 상품이 국가별 samsung.com에서 어떻게 다르게 노출되는지 **실제 렌더링 화면으로 캡쳐**합니다. 그리고 차이점을 카드로 정리한 **로컬 HTML 페이지**를 만듭니다. 사용자는 이 페이지를 직접 보고, 그 내용을 CA·US 데이터 정규화 규칙과 파이프라인(크롤러, 파서, 가격·단위 처리)에 반영합니다.

- 보는 사람: 사용자 1명. 작업 중에 옆에 띄워 두는 참고 자료입니다.
- 1차 관심사: Fold8 Ultra의 **메뉴(구매 페이지에서 차례로 고르는 항목)**와 **가격 구성**. 특히 US는 통신사, 카드 할인 등 구성이 다양하다고 들어서 어디가 다른지 눈으로 확인하고 싶어 합니다.
- 이후 확장: 세탁기, 냉장고 등 카테고리별 주요 상품에 같은 작업을 반복합니다. 따라서 일회성 스크립트가 아니라 **상품을 설정 파일로 추가하는 재사용 도구**여야 합니다.

## 2. 목표 / 비목표 / 안티 목표

**목표**
- G1. 국가·지역·옵션 조합마다 실제 화면을 캡쳐한다(대기, 배너 처리, 지역 선택, 접힌 영역 펼치기, 옵션 선택 후 가격 확정 포함).
- G2. 캡쳐 시점의 값을 함께 기록한다: 최종 URL, 화면에서 읽은 선택 상태, 화면 가격 텍스트, 페이지 소스(JSON-LD) 가격, SKU, 구매 단계 목록, 경고.
- G3. 차이점 카드 중심의 HTML 결과 페이지를 만든다(5장).
- G4. 상품 추가는 설정 파일 1개와 카드 메모 파일 1개로 끝난다. 다시 실행하면 캡쳐와 값은 새로 만들고 카드 메모는 유지한다.

**비목표**
- 장바구니 담기, 결제, 로그인, ID.me 인증, 트레이드인 기기 입력 등 구매 진행.
- 차이점의 자동 판정. 카드는 캡쳐를 본 사람(또는 Claude)이 작성한다. 자동 비교는 "화면 가격 vs JSON-LD 가격"과 "선택 실패" 정도만 한다.
- 정기 실행·모니터링·알림.
- 모바일 화면.

**안티 목표 (기술적으로 돌아가도 실패로 보는 것)**
- 로딩 중 화면(스켈레톤, 가격 빈칸)을 정상 캡쳐로 처리하는 것.
- 캡쳐 라벨과 실제 선택 상태가 다른 것. 예: "512GB"로 저장했는데 화면은 256GB가 선택된 상태.
- CA에서 주 설정이 적용되기 전의 가격을 캡쳐하는 것.
- 확인하지 않은 내용을 사실처럼 쓰는 것. 기존 문서의 **[사실] / [추정] / [미확인]** 표기 규칙을 결과 페이지에도 쓴다.

## 3. 1차 범위: Galaxy Z Fold8 Ultra

### 3.1 대상 URL과 컨텍스트

| 컨텍스트 ID | URL | 지역 설정 |
|---|---|---|
| `uk` | https://www.samsung.com/uk/smartphones/galaxy-z-fold8-ultra/buy/ | 없음 |
| `ca-en-on` | https://www.samsung.com/ca/smartphones/galaxy-z-fold8-ultra/buy/ | Ontario |
| `ca-en-qc` | 같은 URL | Quebec |
| `ca-fr-on` | https://www.samsung.com/ca_fr/smartphones/galaxy-z-fold8-ultra/buy/ | Ontario |
| `ca-fr-qc` | 같은 URL | Québec |
| `us` | https://www.samsung.com/us/smartphones/galaxy-z-fold8-ultra/buy/ | 없음 |

### 3.2 옵션 조합

| 컨텍스트 | 축 | 조합 수 |
|---|---|---|
| UK, CA 4개 | 용량 3개(256GB, 512GB, 1TB) × 색상 고정 | 각 3개, 총 15개 |
| US | 용량 3개 × Connectivity 2개(**Unlocked**, **Verizon**) × 색상 고정 | 6개 |
| 전 컨텍스트 | 기본 용량에서 색상만 바꿔 가격이 같은지 확인 | 컨텍스트당 색상 수만큼(가격 기록 위주) |

- 고정 색상은 **Graphite**입니다. 정적 수집 기준으로 모든 국가·용량에 있는 유일한 색입니다.
- US 통신사는 **Verizon으로 고정**합니다(사용자 결정). 여기에 UK·CA와 비교 기준이 되고 JSON-LD 가격이 붙어 있는 **Unlocked**를 함께 찍습니다(내 판단).
- Verizon을 고른 뒤 나오는 하위 선택지(신규/기기변경, 월납/일시불 등)는 페이지 기본값 그대로 둡니다. 하위 선택지 섹션 자체는 펼쳐서 캡쳐하므로 어떤 선택지가 있는지는 보입니다.
- AT&T, XAU 계열 등 나머지 통신사는 가격 조합에서 뺍니다. Connectivity 섹션 캡쳐로 존재만 확인합니다. 정적 HTML의 SKU 접미사 기준으로는 XAA, ATT, VZW, XAU 4종이 있습니다.
- 어떤 용량에서 Verizon을 고를 수 없으면 실패가 아니라 **"선택 불가"로 기록**합니다. 이것 자체가 차이점입니다.

### 3.3 조합마다 캡쳐할 것

1. 전체 페이지 캡쳐: 부록용입니다. 지연 로딩을 풀기 위해 끝까지 스크롤한 뒤 찍습니다.
2. 구매 단계 섹션별 캡쳐: 페이지에 나오는 섹션을 헤딩 순서대로 찍습니다. 확인된 섹션은 아래와 같습니다.
   - UK: Device, Storage, Colour …
   - CA: 주 선택 바, Device, Storage, Colour, Samsung Trade-In, Annual Upgrade Program …
   - US: Storage, Color, Connectivity …

   그 아래 섹션(Care+, 결제·금융, 카드·프로모션 할인, 요약/고정 가격 바 등)은 실제 캡쳐에서 확인합니다.
3. 가격 영역 캡쳐: 상단 고정 가격 바와 요약 영역입니다.
4. 펼친 상태 캡쳐: 할인·금융·카드 오퍼의 "자세히 보기"류 영역을 펼친 뒤 찍습니다.

트레이드인은 Yes/No 선택지와 안내 문구까지만 캡쳐하고, 기기 입력 단계로는 들어가지 않습니다.

### 3.4 정적 수집으로 이미 확인된 사실 (2026-10-27~28)

| | UK | CA-EN / CA-FR | US |
|---|---|---|---|
| SKU 수 | 12 (`SM-F976B…EUB`) | 10 (`SM-F976W…XAC`), 1TB는 Violet Shadow·Graphite만 | 37 (`SM-F976U…` + XAA/ATT/VZW/XAU) |
| JSON-LD 256/512/1TB | £1,899 / £2,069 / £2,409 | $2,699.99 / $2,979.99 / $3,539.99 CAD | 256GB Unlocked $1,899.99, 정가 $2,099.99 (`priceSpecification` StrikethroughPrice) |

### 3.5 기준 가격 (표와 JSON-LD 비교에 쓰는 값)

- 가격 표와 JSON-LD 비교에는 **기기 일시불 가격**을 씁니다. 추가 옵션은 모두 뺀 상태입니다(트레이드인 No, Care+ 없음, Annual Upgrade Program 미가입). 페이지가 처음부터 추가 옵션을 선택해 둔 상태라면 해제한 뒤 읽습니다.
- 화면 상단에 크게 보이는 가격(headline), 월 할부 문구, 정가(취소선)는 **별도 필드로 함께 기록**합니다. 표에는 기준 가격을 보여 주고, 칸을 누르면 나머지를 보여 줍니다.
- 이 기준은 내 판단입니다.

## 5. 결과 페이지 (A안 + 요약 가격표)

사용자가 브라우저 시안에서 고른 A안(차이점 카드 중심)을 기준으로 합니다. 시안은 `.superpowers/brainstorm/…/content/layout.html`, `layout-a-v2.html`에 있습니다.

한 장짜리 로컬 HTML이며, 이미지는 상대 경로로 넣어 인터넷 없이 열립니다. 위에서 아래로 다음 순서입니다.

1. **머리말**: 캡쳐 시각(KST), 화면 크기, 캡쳐 규칙 요약, 컨텍스트별 URL 표, 경고 개수.
2. **요약**
   - 가격 표: 행은 용량, 열은 컨텍스트(US는 Unlocked·Verizon 2열). 칸을 누르면 해당 조합의 캡쳐로 이동합니다. 화면 가격이 JSON-LD 가격과 다르면 칸을 빨갛게 표시합니다. B안에서 가져온 것으로, 내 제안입니다.
   - 메뉴 구성 표: 행은 구매 단계 섹션, 열은 컨텍스트, 칸은 있음/없음.
   - 차이점 카드 목차: 제목과 태그.
3. **차이점 카드**: 카드 하나에 차이 하나를 담습니다. 각 카드의 구성은 다음과 같습니다.
   - 제목, 태그 1개 이상. 태그는 `국가별 구성 차이`, `사이트 데이터 오류`, `소스 vs 화면 불일치`, `CA-FR 번역` 네 가지입니다.
   - 비교 대상 캡쳐를 나란히 배치합니다. 국가가 같은 영역끼리 놓이고, 다른 부분은 **빨간 박스**로 표시합니다. 이미지를 누르면 원본 크기로 열립니다.
   - 각 캡쳐 아래에 URL과 선택 상태를 적습니다.
   - 관찰 내용에는 [사실]/[추정] 표기를 붙입니다.
   - 정규화·파이프라인 메모를 붙입니다.
4. **부록**: 컨텍스트별·조합별 전체 페이지 캡쳐 갤러리와 수집 값 표(JSON 원본 링크)입니다.

**카드 작성 흐름**
- 캡쳐를 다 찍은 뒤 내가 캡쳐를 보고 카드를 고르고 작성합니다(1차).
- 카드는 상품별 메모 파일에 따로 저장합니다. 메모에는 참조할 조합·섹션, 빨간 박스 위치(텍스트 기준 또는 좌표), 관찰, 메모가 들어갑니다.
- 재실행하면 캡쳐는 새로 바뀌고 카드 메모는 그대로 유지됩니다. 카드가 가리키는 섹션이나 텍스트가 새 캡쳐에 없으면 그 카드에 경고를 표시합니다.

**1차 카드 후보** (실제 캡쳐를 본 뒤 확정)

| 카드 | 태그 |
|---|---|
| 구매 단계(메뉴) 구성 차이 | 국가별 구성 차이 |
| 가격 표기 형식(월 할부·일시불·정가 취소선·세금 문구) | 국가별 구성 차이 |
| US Unlocked vs Verizon 가격과 조건 | 국가별 구성 차이 |
| CA 주별 가격과 조건(ON vs QC) | 국가별 구성 차이 |
| 트레이드인 | 국가별 구성 차이 |
| Care+ | 국가별 구성 차이 |
| 금융·카드 할인(Samsung Finance/Klarna, Affirm/Flexiti, TD Bank/Galaxy Card 등) | 국가별 구성 차이 |
| 색상명 불일치 | 사이트 데이터 오류 |
| 화면 가격 vs JSON-LD 가격 | 소스 vs 화면 불일치 |
| CA-FR 번역 누락 | CA-FR 번역 |

## 6. 재사용 구조

- 상품은 **설정 파일 하나**로 정의합니다. 들어가는 내용은 다음과 같습니다.
  - 컨텍스트별 URL과 지역 설정
  - 옵션 축(라벨 텍스트는 언어별)
  - 고정 옵션
  - 캡쳐할 섹션(언어별 헤딩 텍스트)
  - 펼칠 요소
  - 가격 영역 위치
- 사이트 공통 동작(쿠키 배너, 국가 배너, CA 주 선택, 스크롤·지연 로딩)은 설정이 아니라 코드에서 국가별로 처리합니다. 상품이 바뀌어도 그대로 재사용합니다.
- 가전 PDP는 구매 구성기보다 스펙 섹션이 중요합니다. 그래서 설정이 "펼치기 + 섹션 캡쳐"만으로도 동작하는 형태여야 합니다. 1차에서는 Fold8 Ultra만 실제로 검증하고, 가전용 설정은 만들지 않습니다.

## 7. 기술 선택 (내 판단)

- Python 3.9 이상 + Playwright(Chromium). 기존 보고서의 검증 키트(`verify.py`)와 같은 계열이고, 이 PC에 Playwright 브라우저 캐시가 이미 있습니다. `verify.py`는 이 저장소에 없으므로 코드는 새로 작성합니다.
- 개발 순서: 탐색 실행(실제 페이지에서 섹션·선택지·셀렉터 확인) → 설정 조정 → 전체 실행 → 캡쳐를 보고 카드 작성.
- 위치
  - 코드: `tools/site_compare/`
  - 상품 설정: `tools/site_compare/products/`
  - 카드 메모: `tools/site_compare/cards/`
  - 결과: `out/site_compare/<상품>/<실행시각>/` (git 제외)
- 실행 결과는 `report.html`, `data.json`, `shots/`입니다. 실행이 끝나면 `report.html` 경로를 출력합니다.
- 캡쳐와 페이지 생성은 따로 실행할 수 있어야 합니다. 카드만 고쳤을 때 다시 캡쳐하지 않기 위해서입니다.

## 8. 빌더에게 맡기는 것

- 요소 찾는 방식(셀렉터 vs 텍스트 기준), 대기 로직 세부, 재시도 정책
- 설정·카드 파일 형식(YAML/JSON), 내부 모듈 구조
- 이미지 형식·압축, HTML 스타일(시안의 느낌만 유지)
- 빨간 박스 구현 방식(캡쳐 시 그리기 vs HTML 오버레이)

## 9. 결정 기록

**사용자가 정한 것**
- 대상: Galaxy Z Fold8 Ultra (Fold8 일반 모델 아님)
- 국가: UK(기준), CA-EN, CA-FR, US
- CA는 주 2개
- "메뉴"는 구매 페이지에서 차례로 고르는 항목들(용량, 색상, 통신사, 트레이드인, Care+ 등)
- US 통신사는 Verizon으로 고정
- 조합별 캡쳐, 5초 대기, 접힌 영역 펼치기, 옵션 선택 후 가격 확정, URL 표시
- 결과 페이지는 A안(차이점 카드)
- 이후 세탁기·냉장고 등으로 확장

**내가 정한 것 (사용자 확인 대상)**
- CA 두 번째 주는 Quebec. 기존 문서에 퀘벡 예외(금융 조건, Care+)가 많기 때문입니다.
- 색상은 Graphite로 고정하고, 색상별 가격은 기본 용량에서 1회 확인합니다.
- 트레이드인은 Yes/No 선택지까지만 캡쳐합니다.
- 요약 가격표를 넣습니다(B안 차용).
- 데스크톱 1440px, 쿠키는 거부 우선, 결과물은 git에서 제외합니다.
- US는 Verizon과 함께 Unlocked도 찍습니다(UK·CA 비교 기준, JSON-LD 가격 비교용). Verizon 하위 선택지는 기본값으로 둡니다.
- 기준 가격은 추가 옵션을 뺀 기기 일시불 가격으로 정했습니다(3.5).
- 1차에서는 프록시·VPN을 지원하지 않습니다.
